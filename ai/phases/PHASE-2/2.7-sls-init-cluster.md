# Phase 2.7 — SLS `kubeadm/init_cluster.sls`

## Цель

State файл для инициализации кластера, вызывается только из orchestrate. Работает по фазам через pillar `_phase`.

## Файлы

- `kubeadm/init_cluster.sls`
- `test/unit/test_init_cluster_render.py` (рендеринг тесты — если отсутствует, добавить)

## Зависимости

- Phase 2.1 (`kubeadm.initialized`)
- Phase 2.2 (`kubeadm.healthy`)
- Phase 2.3 (`kubeadm.preflight`)

## Scope

Jinja-рендеринг по `_phase` из pillar:

### `_phase: preflight`
```yaml
kubeadm_preflight:
  kubeadm.preflight:
    - config: {{ config_dir }}/init.yaml
    - pull_images: True
```

### `_phase: init`
```yaml
kubeadm_init:
  kubeadm.initialized:
    - config: {{ config_dir }}/init.yaml
    - patches: {{ patches_dir }}
    - upload_certs: True
    - skip_phases: {{ skip_phases }}
```

### `_phase: health`
```yaml
kubeadm_health:
  kubeadm.healthy:
    - checks: [readyz, etcd]  # НЕ node_ready: нет CNI
    - retries: {{ health.retries }}
    - interval: {{ health.interval }}
```

## Тесты

1. `_phase: preflight` → рендерится state `kubeadm.preflight`
2. `_phase: init` → рендерится state `kubeadm.initialized` с правильными параметрами
3. `_phase: health` → рендерится state `kubeadm.healthy` без node_ready
4. `managed_by: external` для kube-proxy → `skip_phases` содержит `addon/kube-proxy`
